## 〇、一句话

> 众人做的是调度器——转发流量、推荐供应商、闭源黑盒；
> FlowModus 做的是**度量衡**——定义统一标尺，校准声明与实测，检定供应商表现，
> **只呈现数据，不替任何人判断**。

## 一、为什么存在（问题）

2026 年 LLM API 市场高度碎片化：100+ 供应商，各自为战的计费算法、KV Cache 参数、
API 格式、Token 定义。企业 FinOps 无法按模型/任务/部门精确归因成本，开发者疲于
适配，用户被锁进单一供应商的花园。**行业需要真正中立的第三方。**

FlowModus 不是又一个网关，而是**度量衡 + 调度规则的定义者**。

## 二、是什么（定位，独立于任何生态）

- **度量衡局**：STE（标准 Token 当量）统一"度"；声明偏移量统一"校准"；一致性
  测试统一"检定"。跨供应商的报价/能力/诚信度第一次有了可验证的公共标尺；
- **规则定义者**：不控制流量、不推荐供应商、不持有凭证；只提供确定性的调度规则
  引擎与可验证的供应商数据标准；
- **完全独立**：核心协议不依赖任何 Agent 框架或生态（Helix 只是第一个消费者）；
- **去中心化**：无中心服务器；供应商 JSON 经 Ed25519 签名 + IPFS/IPNS 分发；
  密钥永存本地；"不拥有服务器是最大的力量"。

**护城河**：代码可复制、平台可取代，**社区共识不可复制**——"不争市场，只定规则。
不逐流量，只建信任。不卷参数，只立标准。"

## 三、度量衡范式（第一范式）

| 度量衡环节 | FlowModus 对应 | 语义 |
|---|---|---|
| **度**（统一单位） | STE 标准 Token 当量 | 不同 Token 定义/计费方式坍缩为统一标尺（比较辅助，不进入审计） |
| **衡**（统一计价） | Layer 3 标准化计价（Estimated_Cost_USD） | 复杂计费模型坍缩为直观美元数字 |
| **校准**（声明 vs 实测） | 声明偏移量（纯数学偏差百分比） | 自动计算、自动公开、**不做任何评级** |
| **检定**（一致性测试） | 计费精度 / TTL 漂移 / 响应时间一致性 / 语义标签准确度 | 只呈现数据，不设通过标准，不人工审核 |
| **仲裁权** | 用户本地配置 | "所有调度权重默认值均为建议，用户始终拥有最终覆盖权" |

**铁律**：**FlowModus 不判断。FlowModus 只呈现。判断权永远属于用户。**

## 四、五层确定性路由管线（不可变资产）

```
L1 协议与度量规范层 —— STE 定义、Unicode NFC 规范化、协议契约
L2 供应商原始模型层 —— Ed25519 签名注册表；绝对忠实记录原始声明，不含主观评价
L2.5 确定性基准测试层 —— 声明偏移量（真实流量遥测寄生 + 用户显式按需探测，无定时心跳）
L3 标准化计价与评估层 —— Estimated_Cost_USD 成本坍缩
L4 用户偏好与硬边界 —— Hard Filter：预算/地域/合规，无情砍掉不合格者
L5 Agent 意图与动态偏好 —— Soft Weighting：多维向量点积 + 熵增路由防羊群
```

- **五层顺序不可变、不可跳过**；实测数据**永不覆盖**静态声明（偏移量另行记录）；
- **确定性两层定义**：静态规则确定性（声明数据，绝对可复现）+ 动态状态自适应
  （延迟/可用性，辅助决策，有明确熔断阈值——确定性 If-Else，非概率模型）；
- **熵增路由**：Top-N 得分归一化为概率分布，instance-id 去相关——两台相同配置的
  Sidecar 不集体涌入同一供应商（防羊群），同 instance 同输出（确定性保留）。

## 五、核心立场（与世界的分界）

| 立场 | FlowModus | 世界主流（拒绝） |
|---|---|---|
| 身份 | 度量衡局 / 规则定义者 | 网关 / 代理 / 管理台 |
| 路由依据 | 用户约束 + 确定性信号（注册表/成本/硬边界） | 供应商利润 / 黑盒推荐 |
| 数据来源 | **寄生遥测 + 按需探测**（零定时心跳） | 主动探测（每小时 Canary） |
| 凭证 | **零接触**（密钥永存本地，从不传输） | 云端聚合 / 平台代管 |
| 评级 | **不评级，只呈现**（偏移量/一致性数据） | 诚信评分 / 官方推荐 |
| 供应商数据 | 签名注册表（忠实原文） | 代理改写 / 黑盒映射 |
| 去中心化 | IPFS/IPNS + 多签委员会 + 自主接管 | 中心化 SaaS |

## 六、与 Helix 生态的关系（消费者关系，非隶属）

- FlowModus 是**独立协议**；Anaphase / Callosum / Cellrix 是应用层消费者；
- **编排优先，拒造实体**：FlowModus 只提供数据标准（KV Cache 声明/STE/偏移量），
  不干预消费者决策逻辑；
- **judge-points 契约**（Anaphase 需求规格）消费 FlowModus 的模型池调度语义：
  级联升级链（Rules → 3B → L → 本地）由确定性判据驱动——FrugalGPT 实证支撑
  （85%+ 查询无需前沿模型，98% 成本削减），这是应用层范式，非协议本体。

## 七、边界（哪些不是 FlowModus）

- ❌ 不是第三方 API 管理台类的网关或管理台（不造轮子）——展示/管理属消费者 UI；
- ❌ 不持有凭证、不中转流量本体（调度决策本地完成）；
- ❌ 不做权限/分组（CAPABILITY-13 的事）；
- ❌ 不做在线学习路由（RouteLLM 式需训练管线——记未来开放项，不冻结）；
- ❌ 不主动定时探测（manual 铁律 0：唯一例外是用户显式按需探测）；
- ❌ 不内置 UI/daemon/ORM/web 框架（极简依赖铁律）。

## 七·五、供应商注册台（2026-09-09）

- **物理分离**：`registry/free/` 与 `registry/paid/` 一供应商一文件；
  免费 = 所有模型计费全 0（物理事实强制，非标签）。
- **免费优先 = 用户默认偏好（软）**：L5 的 `free_tier_bonus` 默认 +5.0，
  可覆盖——这是 Helix 生存哲学（0 tokens 优先）的呈现，不是协议判断。
- **注册数据用户私有**：端点与密钥偏好 gitignore，零入库；凭证仍不持有（Tuck 唯一门）。
- 详见 ADR-0101。

## 八、未来开放项（不冻结）

- **O-1**：偏好数据升级路径（RouteLLM 式，M3 之后评估）；
- **O-2**：多协议适配器（Anthropic 等）——供应商适配层扩展；
- **O-3**：KV 缓存命中协同（与 Callosum 对齐）——前缀稳定后的成本红利；
- **O-4**：完全拜占庭容错的分布式数据聚合（Sybil 防护，v1.7 已坦率声明为研究课题）。
